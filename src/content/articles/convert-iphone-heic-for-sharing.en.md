A photograph can look ordinary in your iPhone gallery and still be rejected when you select it in a website form. The file may be in HEIC, a format that the receiving site does not accept. Converting iPhone HEIC photos to JPG solves the format problem by making a new JPEG copy. Keep the original, choose which version you want to share, and check what the conversion preserves before deleting anything.

## Find out which file you already have

Open the information panel for the photo or inspect the downloaded file in your file manager. Look for HEIC, HEIF, JPEG or a filename extension. An image shared through a messaging app may already have been converted, reduced in size or stripped of some metadata along the way. If you can access the original file, use it as the conversion source. A copy that has already been reduced by a chat app gives the converter less detail to work with.

Compare the file type with the receiving site's instructions. If JPEG is already accepted and the file is already JPEG, check the size and dimensions before doing anything else. Converting the same photo a second time introduces another encoding step and may have no benefit. If the file ends in .heic and the site demands JPG, export a new file. Renaming the extension only changes the label on the file. The encoded contents remain HEIC and may still be rejected.

## Keep an original and a working copy

Set aside the small group of photos you actually need. If an album holds the only record of a trip, keep the original format and export copies to a separate folder. Name an export based on where it will go, such as application-portrait.jpg or kitchen-listing-02.jpg. Give the original a matching name or record its source filename if you will need to find it again later. Do this before sending several similar photos to different people.

A conversion to JPEG creates a still image. If you care about motion associated with a Live Photo, keep the original in the photo library. A JPEG also has no transparent pixels. For a cutout or graphic where transparency matters, choose a format that supports it and confirm that the destination accepts it. For a regular photo going to a form that lists JPG, a JPEG copy is usually the simplest output to inspect and send.

## Make the JPEG copy

Open the [image converter](/en/convert-image/) and choose the HEIC or HEIF input workflow. Select the file you intend to deliver and set JPEG as the output. Export it, then find the new JPG in the downloads folder. If your phone presents a file picker with several representations of the same picture, check the filename and preview before converting so you can distinguish the primary photo from a screenshot or an edited copy.

Compare both images side by side at a similar display size. Check portrait or landscape orientation and the position of the subject. Some files describe orientation using metadata. If the upload preview suddenly shows a sideways image, open the actual exported file in another viewer to determine whether the saved pixels are rotated or only the portal's preview is unusual. Correct orientation in a fresh copy from the original, then check that the portal and your local viewer agree.

Review shadows, bright areas and saturated colours. Phone photo pipelines can store more colour or contrast information than a plain JPEG represents. A conversion can therefore look different, especially on very bright subjects. Judge skin, white paper and dark details in the output you are about to send. If it looks too flat or one important area has lost detail, make an edited copy in your photo app and use that version as a source.

## Resize or compress only if the destination asks

If a form has exact dimensions, note them as width and height in pixels. Crop or fit the image in the [resize tool](/en/resize-image/) and check the framing first. A landscape source forced into a tall rectangle will stretch if you do not choose cropping or padding. For an upload limit in KB or MB, compare the size of the exported JPEG with the limit. If the file is too large, use the [image compressor](/en/compress-image/) and inspect the result after saving it.

When both constraints apply, pick the shape and pixel dimensions first, then make the smallest quality change that meets the byte limit. Keep some room below the cap if the portal rounds its display. Look at details that matter for that upload, such as a label on a product, a row of text or the edge around a face. If the output gets too soft, use a clean original at the required dimensions and try a less aggressive setting. For repeated submissions, label finished exports with their purpose, size or version so the right copy is easy to select.

## Troubleshoot an output that still fails

A website can reject a valid JPEG for reasons unrelated to HEIC. Check for an exceeded size limit, a minimum width, a required orientation or an unexpected active file selection. Move the old file out of your upload folder if its name makes it easy to confuse with the new one. Inspect the chosen attachment in the portal and open it from the same folder again if its displayed size is surprising.

If conversion itself fails, try opening the source in the device's photo viewer. A file that was only partially transferred or that is stored remotely may need to be retrieved again. Download the original or export a JPEG from the photo app if it supports the image. If one HEIC works and another consistently fails, keep both originals and handle the problematic file separately. Avoid sending a sensitive image through unrelated services just to see whether an error goes away.

For sharing with another person, send the intended JPG and confirm which app will open it. If a messaging app offers a document or file attachment option, compare the received version with the original export when exact dimensions matter. For an online form, wait for a successful confirmation before discarding your working copies. Keep the HEIC as your starting point whenever you need to make another version.
